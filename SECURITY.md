# Security Policy

## Supported Versions

We provide security patches and dependency updates for the active release branch:

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1.0 | :x:                |

## Reporting a Vulnerability

The Stellar Learn team takes the security of our platform, user accounts, and testnet interactions seriously. If you discover a security vulnerability, please give us the opportunity to fix it before making it public.

### How to Report

Please **do not open a public GitHub issue** for sensitive security vulnerabilities.

Instead, report security vulnerabilities by emailing the maintainer:

- **Email**: `noevidence1017@gmail.com`
- **Subject line**: `[Security Vulnerability] Short description`

### What to Include

To help us triage and resolve the issue quickly, please include:

- A description of the vulnerability and its potential impact.
- Step-by-step reproduction instructions or a minimal proof of concept.
- The affected component (e.g. `apps/web`, `packages/game-engine`, API endpoints, or database operations).
- Any potential remediations or patches you have developed.

### Response Timeline

- **Initial Acknowledgement**: Within 48 hours of receipt.
- **Triage and Assessment**: Within 5 business days with severity assessment and mitigation plan.
- **Fix and Disclosure**: We aim to release a patch within 14 days, followed by coordinated disclosure credit to the reporter.

### Safe Harbor

We consider security research conducted in good faith under this policy to be authorized. We will not pursue legal action against individuals who:

- Make a good faith effort to avoid privacy violations, destruction of data, and service interruption.
- Do not exploit a security issue beyond the minimum necessary to demonstrate its presence.
- Give us reasonable time to address the issue before public disclosure.
